# MetroPulse — Current Project Status

**Last Updated:** 2026-11-12

## Current Project Direction

MetroPulse is an AI-driven train induction planning and scheduling system for Kochi Metro Rail Limited (KMRL).

The project migrated to a verified-data approach on 2026-10-15 and was **rebuilt on real GTFS trip records on 2026-11-12**. The earlier synthetic-trip schedule (250 `T0000` trips, FEASIBLE, ~306 s, 93.4% gap) is superseded.

Sources of truth:
- KMRL GTFS static feed (2024-25) — real trip records
- KMRL Annual Report 2024-25 — route length, operating hours
- 2026 news article — fleet breakdown
- Synthetic assumptions where verified operational data is unavailable (clearly tagged)

- Streamlit

Findings from the 2026-11-12 rebuild
[FINDING] add_obj6_rake_balance makes the model INFEASIBLE when build_objective is not called. The o6 call must be commented out in feasibility-probe mode. See constraints-v2.1 §6/§8.

[FINDING] R6 requires per-order gap values (gap_ab and gap_ba). The earlier one-gap-per-pair rule allowed cross-terminal switches (ALVA↔MUTT, TPHT↔MUTT) with gaps between 5 and 15 min. See constraints-v2.1 §5 R6.

[FINDING] Fleet-size behaviour:

232 trips, 18 rakes, 9/9 split → OPTIMAL (~29 s)

250 trips, 18 rakes, 9/9 split → INFEASIBLE (insufficient MUTT coverage)

250 trips, 18 rakes, 9/7/2 split → OPTIMAL (~28.7 s)

Adding more rakes does not fix the 250 case if the split does not include MUTTOM-origin rakes.
